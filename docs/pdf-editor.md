# Harkas Admin PDF editor

Embedded-font coverage: before accepting newly introduced characters, the editor checks the actual embedded font's Unicode mapping and visible outline in addition to PDF text extraction. PDFium may substitute a glyph internally even though PDF.js and other readers cannot render it from the saved font. Missing letters now block applying the edit, identify the affected characters and offer loading the complete original TTF/OTF or an explicit replacement font. Unverifiable embedded font formats also require loading a supported font. The error hides the stale preview. A synthetic incomplete-font regression checks uppercase Y and verifies the replacement keeps size and placement; no customer document is included in the tests.

Route: `/admin/pdf-editor`, behind the existing admin-only route and sidebar permissions. PDFs in Documenten have a direct edit link. The editor does not introduce a new database or public storage bucket.

Supported: open local PDFs or the current private document revision, text overlays with an embedded Unicode font, translucent highlights, frames, freehand drawing, PNG/JPEG images, dragging and image sizing, page rotation/reordering/duplication/deletion, multi-file merge, single-page extraction, undo/redo, download, and save as a copy or optimistic-concurrency-protected revision. Original vector pages and selectable text are copied rather than rasterized. Browser rendering resources and the worker are served from the same origin.

Limits: 50 MB per PDF, 100 MB combined source data, 250 pages, 10 MB/40 megapixels per image, 50 undo steps. Encrypted PDFs are rejected. Source PDFs are kept in session memory; only explicit save uploads to the existing private `admin-documents` bucket. New revisions always use new storage objects. The existing RPC preserves folder/customer metadata and rejects stale expected versions. A failed registration may leave an unreferenced immutable storage object, consistent with the existing document upload flow; it never overwrites a saved revision.

Text-fragment verification: inspection and edit validation group PDFium characters by their owning text object and exclude only generated layout separators. PDFium’s object-text getter can append an inferred space from the next fragment after shortening text, which previously caused a false missing-font error for values such as “21”. Real spaces within the selected object are retained. Neutral adjacent-fragment tests exercise original fonts, full TTF and OTF, short numeric replacements, actual leading/internal/trailing spaces and unchanged neighbors. A read-only copy of the installed Windows Verdana font was used for additional local diagnosis, without adding that font or a customer PDF to the repository.

Digital text: PDFium runs in a dedicated worker and exposes clickable, visible top-level text objects. Editing replaces the real PDF text object, retaining the original font, size, color and transformation matrix. A live preview renders the modified PDF itself, rather than approximating its font in an HTML input. Missing characters in subset fonts fail without changing the document; the user can load the complete original TTF/OTF, or explicitly select DejaVu Sans. Empty text deletes the selected object. A PDF can contain several text fragments per visual line. Nested/shared form text, invisible OCR text, clipping text and multiline objects are skipped. Complex RTL/Indic shaping is not supported by the replacement path and is rejected explicitly. Longer replacements can push contiguous text fragments on the same baseline forward, preserving their spacing. The default-enabled checkbox can disable this for fixed layouts; separate columns, other lines, images and graphics are not reflowed. The real-PDF preview shows the result and page overflow blocks application.

Full font files: the text dialog accepts static, outline-based TTF and OTF files up to 20 MB. Metadata identifies the actual font and variant, and a name mismatch is shown before applying. The complete original font program is embedded (not subsetted), preserving the selected text object's size, RGB color and matrix. TTF and CFF/OpenType use a temporary one-page carrier PDF imported into PDFium; the carrier page is removed before saving. CFF/OpenType uses the proper FontFile3/OpenType and CIDFontType0 dictionaries. Character coverage is checked before preview/application. Malformed files, collections, web fonts, variable fonts, unavailable glyphs and fonts whose embedding flags prohibit editable embedding are rejected without changing the document. Loading a subset file cannot reconstruct characters absent from it: users must supply the complete font and matching normal/bold/italic variant. No proprietary fonts are downloaded automatically.

Installed fonts: on supporting HTTPS desktop browsers, “Automatisch ophalen” requests the browser’s local-fonts permission from an explicit click. The editor enumerates metadata and reads only a face whose PostScript/full name (or regular-family name) matches the original; ambiguous matches are rejected, and bold/italic faces are not substituted for regular. File metadata is validated again against the original name. Existing permission can be reused when the user opens another text dialog; no prompt is triggered on dialog mount. Permission is checked before and after reading font bytes. If an original subset rejects new text, a matching loaded font or permitted installed font is selected automatically and the real PDF preview is rebuilt. The user still applies the result explicitly. Unsupported browsers, denied permission, absent fonts and restricted/unsupported files retain the manual TTF/OTF path; no fonts are downloaded from third parties and metadata is not sent to a server. Browser permission persists according to the browser; the loaded font cache remains session-only.

Loaded font files remain in browser memory (up to eight fonts and 40 MB total, oldest evicted); they can be reused across text dialogs until refresh. There is no separate font upload or font storage backend. Preview and exported PDF contain the full selected font; existing explicit save/download behavior handles the resulting document. Neutral automated fixtures verify exact embedded font-byte equality, reopening and adding new characters, TTF and OTF, four page rotations/crops, unchanged neighbors/page count and the upload limits. Browser QA exercised TTF/OTF file selection, cached reuse, invalid file rejection, rendered uppercase/accent/currency text and application of the result.

OCR: Tesseract runs locally in a worker with self-hosted Dutch and English language data. Recognition runs on the selected page with bounded rendering (12 MP), progress, cancellation and timeout. Recognized lines are clickable; the user reviews their text, confidence and estimated size. OCR cannot recover the original font. Scan corrections use editable DejaVu Sans text over an opaque background rectangle. The original scan remains under the correction; the UI explicitly says this is not suitable for redaction. No document content goes to an OCR provider.

Digital edits create immutable single-page sources for the undo history; duplicate pages and other source pages remain unchanged. Undo retains up to 50 steps, trimmed further at a 150 MB source budget; unused source proxies are released. A persistent download link provides a fallback if automatic downloads are blocked and is invalidated whenever the document changes. Exported additions become fixed PDF content, while editable overlays live in the current session. Existing form values are flattened on export. Drawn signatures are graphical marks, not certificate signatures. Do not describe this as secure redaction or as maintaining digital signature validity.

Verification: `npm run test:pdf` covers real text replacement/deletion with preserved original font/size/color/matrix, four native rotations with crop boxes, embedded subset character rejection and explicit fallback, unchanged neighboring pages, stale edits, nested object safeguards, OCR from a synthetic raster page, and selectable original/new Unicode text, all 16 original/additional rotation combinations including offset crop boxes, merging, reordering, duplication, source immutability, unsupported characters and invalid exports. `npm run build` runs asset preparation and the production build. Full-project typechecking currently has unrelated pre-existing errors in the Supabase client module access type, AdminBtwOverzicht and AdminParking; no PDF-editor errors were reported.

The PDF.js runtime files in `public/pdfjs-assets` are generated by prebuild/predev and are not committed. The bundled DejaVu Sans font's license is included alongside it.

Browser validation: uploaded a two-page PDF, clicked a recognized line, changed it with Helvetica 24 pt retained, checked the rendered result, and exercised undo/redo. Uploaded a raster-only PDF, recognized four lines and replaced a scan heading. The clean raster fixture is recognized correctly in the OCR test; degraded scans expose confidence and require review. The cloud browser did not return a download event for blob URLs (including a visible fallback link), so retrieval/re-upload in that environment remains unverified. Export bytes are validated independently by the PDF integration tests. Private document persistence continues to use the existing storage/RPC path; no production document was changed during these tests.

Text positioning: “Tekst verplaatsen” exposes selectable text objects. Drag to move, Shift/Ctrl-click for multiple selection, use screen-oriented arrow keys (Shift gives 10× steps) or the sidebar direction buttons. “Op één tekstregel” aligns the selected objects to the first selected baseline; dragging a single object snaps to other baselines within five screen pixels, unless Alt is held or snapping is disabled. Moves translate real PDF objects without re-encoding glyphs, so incomplete fonts do not need to be replaced just to move text. Movement is clamped to the visible crop, works across native/editor rotations, preserves other pages and participates in the existing immutable undo/export/save pipeline. New text overlays can also be nudged in Selecteren. Scanned pixels must first be corrected as an OCR overlay; nested/invisible text remains excluded.

`tests/pdf-text-layout.test.mjs` verifies growth without overlap, unchanged separate columns/lines/pages, full-font reflow, native object translation, baseline alignment and snapping, crop limits, stale selections, invalid moves, all 16 combinations of native/editor rotation, and immutable source bytes.
